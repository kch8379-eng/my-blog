# 픽셀 아트 에디터 Review

## 1. 결론
**수정 후 통과** (Embed 항목과 실기기 항목 제외). 그리기, 도구, 팔레트, 되돌리기, PNG 저장(512×512, 픽셀 값), 자동 저장, `?preview`는 브라우저에서 직접 확인해 통과했다. 720px 부근에서 도구 줄 버튼이 겹치는 레이아웃 문제 1건과 favicon 404 1건을 고쳤다.

## 2. 체크리스트 결과 (spec.md 10장)

**그리기**

- [통과] 같은 칸 반복: 같은 칸에서 `pointermove` 10회 후 되돌리기 1번으로 원상 복구(기록 1건).

- [통과] 마우스, 터치, 펜 모두 동작. 두 번째 포인터와 마우스 오른쪽 버튼은 무시됨.

**도구·팔레트**

- [통과] 사용자 지정 색 `#ABCDEF` 입력이 소문자 `#abcdef`로 선택되고 그림과 자동 저장에도 소문자로 들어감.
- [통과] 격자선 토글은 화면에만 영향. 격자 켠/끈 상태의 PNG 바이트가 완전히 동일.

**PNG 저장**

- [통과] 빈 그림: 다운로드 0회, Blob 생성 0회, "그린 내용이 없습니다" 표시.

**코드 검토**

- 팔레트 컨테이너는 `role="group"`이며 선택 상태는 `aria-pressed`로 표시(계획서가 허용한 방식).

## 3. 발견한 문제와 조치

| # | 문제 | 심각도 | 조치 |
|---|---|---|---|
| 1 | 720px 이상 2열 배치에서 오른쪽 열이 152px(720px 화면)로 좁아 도구 버튼 4개가 겹치고 열 밖으로 넘침. 글자도 한 글자씩 줄바꿈됨. | 중간 (레이아웃, 720~약 860px 폭) | 수정함 |
| 2 | `favicon.ico` 요청이 404 (콘솔 에러 표시). | 낮음 | 수정함 |

**수정 내역**
- `apps/pixel-art/style.css`: 720px 이상 규칙에서 `grid-template-columns`를 `minmax(0, 512px) minmax(0, 1fr)`에서 `minmax(0, 512px) minmax(280px, 1fr)`로 바꿔 오른쪽 열 최소 폭을 280px 보장(720px에서 캔버스는 약 384px로 줄고, 880px 앱 폭에서는 512px 유지). 같은 규칙 안의 `.toolbar`에 `grid-template-columns: repeat(2, minmax(0, 1fr))`를 추가해 도구 줄을 2×2로 배치. 이유: 좁은 열에서 4등분하면 글자가 줄바꿈되어 버튼이 커지거나 겹침. 계획서의 "도구 줄 4등분"은 모바일 기준이며 2열 배치에서는 달라짐.
- `apps/pixel-art/index.html`: `<head>`에 `<link rel="icon" href="data:,">` 추가. 이유: favicon 404 제거. 스크립트가 스타일시트보다 먼저 실행되는 순서는 그대로.
- 수정 후 확인: 720px(캔버스 380, 열 384px+280px, 도구 버튼 136×44 2×2, 겹침 없음), 1000px(열 512px+312px, 클릭한 칸과 칠해진 칸 일치), favicon 404 새로 생기지 않음.
- `editor.js`, `export.js`, `main.js`는 수정하지 않음.

## 4. 남은 문제
- 720~860px 폭에서는 동작 줄(되돌리기, 다시 실행, 모두 지우기)이 2줄로 감김(버튼은 44px 이상이고 넘치지 않음). 사용성 문제는 없어 그대로 둠.
- 사용자 지정 색을 팔레트 색이 아닌 체크무늬 색(`#cfd3d8`, `#e4e7eb`)으로 고르면 화면에서 투명 칸과 구분이 어려움(PNG는 정상). 매우 드문 경우라 그대로 둠.
- 미확인: 모바일 실기기에서의 터치 스크롤 방지 체감과 PNG 저장, 인앱 브라우저의 `download` 대체 안내, 블로그 메인 카드 삽입(Embed), 깜빡임(FOUC)의 눈으로 보는 확인, `prefers-reduced-motion`(이 앱은 별도 처리 없음).

## 5. 확인 방법
- 앱: `http://localhost:8000/apps/pixel-art/index.html`, 미리보기: `?preview`. 서버는 시작하거나 멈추지 않음. 확인 전 `fetch(url, { cache: 'reload' })`로 다섯 파일을 다시 받고 새로고침.
- 입력: 캔버스에 `PointerEvent`(mouse, touch, pen)를 합성해 디스패치, 큰 간격 이동과 격자 밖 좌표 포함. 결과는 화면 캔버스의 `getImageData`로 읽음.
- PNG: `URL.createObjectURL`과 `HTMLAnchorElement.prototype.click`을 가로채 Blob과 `download` 속성을 기록, 바이트로 시그니처와 IHDR를 읽고 `createImageBitmap`으로 디코드해 512×512 오프스크린 캔버스에서 칸별 픽셀을 비교.
- 저장·복원: 손상된 값을 넣은 같은 출처 iframe을 불러 결과 확인, `localStorage` 차단은 `srcdoc` iframe에서 `Storage.prototype` 메서드가 예외를 던지게 바꿔 확인.
- 화면: 모바일 프리셋(375px), 사용자 지정 320, 720, 900, 1000px에서 크기, 가로 스크롤, 버튼 크기, 글자 크기, 대비비(실제 계산된 색으로 계산) 측정과 스크린샷 확인. 라이트/다크 모두 확인.
- 오류: 콘솔 메시지, 네트워크 요청과 `performance` 리소스 상태 확인.
- 정리: 화면 크기를 desktop으로 복원하고 `localStorage`의 `pixel-art:draft`, `theme` 삭제.
