# 픽셀 아트 에디터 구현 계획서

> 상태: **승인됨** (2026-11-02, 미정 사항은 모두 권장안으로 확정). Build 진행 가능.
>
> **확정된 결정**
> 1. PNG 출력 크기: 512×512 고정
> 2. PNG 배경: 투명 고정
> 3. 모두 지우기: 확인창 없이 즉시 지우고 되돌리기로 복구
> 4. 진행 중인 그림 자동 저장: 포함
> 5. 키보드로 그리기: 제외 (도구·팔레트·저장은 키보드로 조작 가능)
> 6. 블로그 카드 미리보기: iframe (`?preview`)
> 7. 격자 크기: 16×16 고정

## 1. 개요
16×16 격자에 도트를 찍어 그림을 그리고, 완성하면 PNG 파일로 저장하는 웹앱이다.
`apps/pixel-art/` 안에서 자체 완결되는 순수 HTML/CSS/JS 앱이며, 마우스·터치·펜으로 모두 그릴 수 있다.
블로그의 라이트/다크 테마를 따르는 화면을 쓰되, 사용자가 그린 그림의 색은 테마에 따라 바뀌지 않는다.

## 3. 그리기 동작

### 입력 통합
- **Pointer Events**(`pointerdown` / `pointermove` / `pointerup` / `pointercancel`)로 마우스·터치·펜을 한 경로로 처리한다. `touchstart` 계열은 쓰지 않는다.
- 캔버스에 CSS `touch-action: none`을 주어 그리는 중 페이지가 스크롤·확대되지 않게 한다. `contextmenu` 이벤트는 캔버스에서 막는다(길게 눌렀을 때 메뉴 방지).
- `pointerdown`에서 `setPointerCapture`를 호출해, 드래그 중 포인터가 캔버스 밖으로 나가도 이벤트를 계속 받는다.
- 활성 포인터 ID를 하나만 기억한다. 이미 그리는 중에 들어온 다른 포인터(두 번째 손가락)는 무시한다. 마우스는 주 버튼(`button === 0`)만 허용한다.
- 획 종료는 `pointerup`, `pointercancel`, `lostpointercapture` 어느 쪽이든 한 번만 처리한다.

### 한 칸 칠하기
- `pointerdown` 위치의 칸을 현재 도구(연필 = 선택 색, 지우개 = 투명)로 즉시 칠한다. 한 번 탭하면 한 칸이 찍힌다.

### 드래그로 이어 칠하기 (칸이 빠지지 않게)
- 빠르게 움직이면 `pointermove` 사이에 여러 칸을 건너뛴다. 해결책: **직전 칸에서 현재 칸까지 Bresenham 직선**의 모든 칸을 칠한다.
- 지원 브라우저에서는 `event.getCoalescedEvents()`로 합쳐진 중간 샘플도 순서대로 처리한다. 없으면 이벤트 하나만 쓴다.
- 직선 계산은 `editor.js`의 순수 함수(`lineCells(x0, y0, x1, y1)`)로 두어 DOM 없이 확인할 수 있게 한다.

### 같은 칸 반복 처리
- 이미 같은 색인 칸은 다시 칠하지 않는다(`setCell`이 변경 여부를 `true/false`로 돌려줌). 같은 칸 위에서 `pointermove`가 계속 와도 렌더링·기록이 늘지 않는다.
- 한 획에서 실제로 바뀐 칸이 하나도 없으면 되돌리기 기록을 남기지 않는다.

### 격자 밖으로 나갔을 때
- 칸 좌표는 **범위로 자르지 않고** 가상 좌표(음수나 16 이상도 허용)로 계산한다. 직선 계산 후 **격자 안에 있는 칸만** 칠한다.
- 효과: 가장자리 바깥으로 나갔다가 다시 들어와도 선이 자연스럽게 이어지고, 바깥에서는 아무것도 칠하지 않는다. 가장자리 바로 바깥을 따라 긋는 경우도 안쪽 가장자리 칸이 빠지지 않는다.
- 획은 포인터를 뗄 때까지 유지된다(캡처 덕분).

### 스포이트
- 칸을 누르면 그 칸의 색을 선택 색으로 삼고 연필로 돌아간다. 빈(투명) 칸이면 지우개로 전환한다. 드래그하지 않는다(탭 한 번).

## 4. 색상 팔레트

### 기본 색 (16색, 테마와 무관한 고정 값)
PICO-8 팔레트에서 8번째를 순백으로 바꾼 구성이다.

| # | 이름 | 값 | # | 이름 | 값 |
|---|---|---|---|---|---|
| 1 | 검정 | `#000000` | 9 | 빨강 | `#ff004d` |
| 2 | 남색 | `#1d2b53` | 10 | 주황 | `#ffa300` |
| 3 | 자주 | `#7e2553` | 11 | 노랑 | `#ffec27` |
| 4 | 초록 | `#008751` | 12 | 연두 | `#00e436` |
| 5 | 갈색 | `#ab5236` | 13 | 하늘 | `#29adff` |
| 6 | 짙은 회색 | `#5f574f` | 14 | 보라 | `#83769c` |
| 7 | 회색 | `#c2c3c7` | 15 | 분홍 | `#ff77a8` |
| 8 | 흰색 | `#ffffff` | 16 | 살구 | `#ffccaa` |

- 기본 선택 색은 검정. 색 값은 `main.js` 상단의 상수 배열(이름 포함)로 둔다. 이름은 버튼의 `aria-label`과 `title`에 쓴다.
- **라이트/다크 어디서나 구분**: 그림이 그려지는 캔버스 바탕은 **테마와 무관한 고정색**(체크무늬 `#cfd3d8` / `#e4e7eb`)이다. 투명 칸과 흰색 칸을 구분하기 위해 순백 대신 회색 체크무늬를 쓴다. 검정은 밝은 바탕에서, 흰색은 회색 체크무늬 위 격자선 안에서 보인다. 팔레트 견본 버튼은 `2px solid var(--muted)` 테두리로 감싸 어두운 배경에서도 검정·남색 견본 윤곽이 보이게 한다(윤곽 대비 3:1 이상 목표).
- 캔버스 색, 격자선 색, 팔레트 색은 CSS 변수가 아니라 **고정 상수**로 쓴다(테마 전환에 영향받지 않음). 앱 UI(버튼, 배경, 글자)만 테마 변수를 쓴다.

### 선택 표시 방식
- 선택된 견본은 **이중 링**: 바깥 3px `var(--accent)` 테두리 + 안쪽 2px `var(--bg)` 간격. 어떤 색 위에서도 보이고, 색만으로 구분하지 않는다.
- 팔레트는 `role="radiogroup"` 안의 버튼들이며 선택된 것에 `aria-checked="true"`(또는 `aria-pressed`)를 둔다. 현재 선택 색 이름과 값을 도구 줄 옆에 텍스트로도 보여 준다(예: `선택: 빨강 #ff004d`).
- 지우개 선택 중에는 팔레트 링을 끄지 않고, 도구 버튼의 눌림 상태로 지우개 사용 중임을 나타낸다.

### 사용자 지정 색
- 지원한다(P2). 팔레트 끝에 `<input type="color">` 견본 한 칸을 둔다. 값이 바뀌면 그 색이 선택 색이 된다. 최근 사용 색 목록은 만들지 않는다.
- 저장되는 색 값은 항상 소문자 `#rrggbb`로 정규화한다.

## 5. PNG 저장

- **출력 해상도: 512×512 (16×16을 32배)**. 정수 배율이라 모든 도트가 같은 크기 정사각형이다.
- **흐려지지 않게 하는 방법**: 16×16 캔버스를 키워 그리지 않는다. 별도의 **오프스크린 캔버스(512×512)** 를 만들고, 칸마다 `fillRect(x*32, y*32, 32, 32)`로 직접 칠한다. 칸 경계가 정수 픽셀이므로 보간이 개입하지 않는다. (보조로 `imageSmoothingEnabled = false`도 설정.) 화면용 캔버스(격자선, 체크무늬 포함)를 복사하지 않는다.
- **배경: 투명**. 칠하지 않은 칸은 알파 0으로 남긴다(체크무늬·격자선은 PNG에 넣지 않음). 흰 배경 옵션은 이번 범위에서 제외(미정 사항 참고).
- **파일 이름**: `pixel-art-YYYYMMDD-HHmmss.png` (로컬 시각 기준).
- **다운로드 방식**: `canvas.toBlob(cb, 'image/png')` → `URL.createObjectURL(blob)` → 임시 `<a download="파일명" href=blob:...>`를 만들어 `click()` → 잠시 뒤(약 1초) `URL.revokeObjectURL`. 외부 라이브러리는 쓰지 않는다. `toBlob`이 `null`을 돌려주면 오류 안내를 상태 문구로 보여 준다.
- 저장 후 상태 문구(`aria-live="polite"`)에 `저장했습니다 (512×512 PNG)`를 보여 준다. 아무것도 칠하지 않은 상태로 누르면 저장하지 않고 `그린 내용이 없습니다`를 보여 준다.
- **모바일 한계와 대응**
  - iOS Safari(13+), Android Chrome은 `a[download]`로 저장되지만 저장 위치(파일 앱, 다운로드 폴더)는 브라우저가 정한다.
  - 인앱 브라우저(카카오톡 등)나 일부 구형 환경은 `download` 속성을 무시하거나 이미지를 새 화면으로 열기만 한다.
  - 대응(P3): 저장 시 마지막으로 만든 PNG를 `<img>`로 `<details>` "저장이 안 되나요?" 안에 넣어 두고 "이미지를 길게 눌러 저장하세요"라고 안내한다. 이 `<img>`의 blob URL은 다음 저장 때까지 유지하고 그때 해제한다. 이미지 확대 시 흐려지지 않도록 `image-rendering: pixelated`를 준다.
  - Web Share API는 쓰지 않는다(복잡도 대비 이득이 작음).

## 6. 파일 구조

```
apps/pixel-art/
├── index.html    # 마크업(도구 줄, 캔버스, 팔레트, 저장 영역), 테마·preview 초기화 인라인 스크립트
├── style.css     # 색상 변수(라이트/다크), 레이아웃, 버튼·팔레트 스타일
├── editor.js     # 순수 로직 (DOM 접근 없음): 그림 데이터, setCell, lineCells, 되돌리기 기록, 직렬화/검증
├── export.js     # PNG 생성: 데이터 → 오프스크린 캔버스 → Blob (DOM 이벤트 없음)
├── main.js       # 진입점: 캔버스 렌더링, 입력(Pointer Events), 도구·팔레트 UI, 자동 저장, 다운로드 실행, ?preview
├── spec.md       # 이 계획서
└── review.md     # Review 단계에서 작성
```
- `editor.js` / `export.js` / `main.js`는 ES 모듈(`<script type="module">`)로 연결한다. 전역 변수를 만들지 않는다.
- 외부 라이브러리·CDN·웹 폰트 없음. 시스템 폰트 스택 사용. 블로그의 `css/theme.css`는 참조하지 않고 같은 변수 이름·값을 `style.css`에 복제한다(2048과 동일).
- 코딩 규칙은 블로그와 동일: 공백 2칸, 세미콜론, 작은따옴표, 클래스 `kebab-case`, 변수 `camelCase`, 한국어 주석, `innerHTML` 미사용(`textContent`, `replaceChildren` 사용).
- 의존 방향: `main.js` → `editor.js`, `export.js`. `editor.js`는 아무것도 가져오지 않는다.

## 7. 화면 설계

### 렌더링 방식: `<canvas>` (DOM 격자 아님)
- 이유: 256개 `div`보다 드래그 중 갱신이 가볍고, 격자선·체크무늬를 정확히 그릴 수 있으며, 좌표 계산이 `getBoundingClientRect` 한 번으로 끝난다. PNG 내보내기와 렌더링 코드를 비슷하게 쓸 수 있다.
- 단점(접근성): 칸이 개별 요소가 아니다. 완화: 캔버스에 `role="img"`와 `aria-label="16×16 픽셀 아트 캔버스"`를 주고, 키보드 그리기는 이번 범위에서 제외한다(미정 사항 참고). **`role="img"` 요소 안에 다른 컨트롤을 넣지 않는다**(2048 리뷰에서 나온 교훈). 캔버스는 자식 없이 단독으로 두고 컨트롤은 형제 요소로 둔다.
- 선명도: 캔버스 내부 해상도는 `floor(CSS폭 × devicePixelRatio / 16) × 16`(16의 배수)으로 맞춰 칸 경계가 장치 픽셀에 맞게 한다. `ResizeObserver`로 크기가 바뀔 때 다시 설정·그린다. 그리기는 `requestAnimationFrame`으로 모아 한 프레임에 한 번만 한다.
- 화면 그리기 순서: 체크무늬 바탕 → 칸 색 → 격자선(켜져 있을 때, `rgba(128,128,128,0.45)` 1장치픽셀 선).

### 레이아웃 (위에서 아래로, 모바일 우선)
1. **헤더 줄**: 왼쪽 제목 "픽셀 아트 에디터", 오른쪽 "← 블로그" 링크(`../../index.html`, 높이 44px).
2. **도구 줄**: `연필` `지우개` `스포이트` `격자` — 가로 4등분 토글 버튼(`aria-pressed`). 격자는 도구가 아니라 표시 옵션 토글이라 시각적으로 구분(구분선 또는 다른 스타일)한다.
3. **캔버스**: 정사각형. `width: min(100%, 512px)`, `aspect-ratio: 1`, `2px solid var(--muted)` 테두리, 모서리는 둥글게 하지 않는다(도트 가장자리 일치). `touch-action: none`.
4. **팔레트**: `display: grid; grid-template-columns: repeat(auto-fill, minmax(44px, 1fr)); gap: 8px;` 견본 16개 + 사용자 지정 색 1개. 아래에 현재 선택 색 텍스트.
5. **동작 줄**: `되돌리기` `다시 실행` `모두 지우기` 3등분 버튼.
6. **저장 영역**: `PNG 저장`(주 버튼, 전폭), 상태 문구, `<details>` 저장 대체 안내.

| 폭 | 배치 |

| 375px (기본) | 위 순서대로 한 컬럼. 앱 좌우 여백 16px, 캔버스 약 343×343. 팔레트는 6열 × 3행(견본 한 변 약 47px). 도구 줄·동작 줄은 3~4등분 전폭(버튼 폭 약 80~110px, 높이 44px). 가로 스크롤 없음. 세로로 한 화면에 팔레트까지 들어오는 것을 목표로 한다(저장 버튼은 스크롤 허용). |
| 320px | 팔레트 5열, 버튼 글자가 줄바꿈되어도 높이가 늘어날 뿐 넘치지 않게 한다. |
| 720px 이상 | 2열 그리드: 왼쪽 캔버스, 오른쪽 도구·팔레트·동작·저장. 앱 최대 폭 약 880px, 가운데 정렬. |
| 가로 모드(낮은 높이) | 캔버스는 `max-height: 80vh` 안에서 정사각형 유지(폭을 같이 줄임), 폭이 충분하면 720px 규칙의 2열이 적용된다. |

- 터치 대상: 모든 버튼·견본·링크 최소 44×44px. 본문·버튼 글자 16px(1rem) 이상.
- 색: 앱 UI는 모두 CSS 변수. 기본은 `prefers-color-scheme`, `localStorage['theme']`가 `light`/`dark`면 `<html data-theme>`로 덮어쓴다. `<head>` 인라인 스크립트로 FOUC를 막는다(2048과 동일한 한 줄 스크립트, `?preview`면 `<html class="preview">`도 추가).
- 변수는 2048 `style.css`의 공통 값(`--bg --surface --text --muted --accent --on-accent --border`)을 그대로 복제한다. 도구 버튼 눌림 상태는 `--accent` 배경 + `--on-accent` 글자(대비 4.5:1 이상은 2048 리뷰에서 확인된 쌍이므로 재사용).
- `prefers-reduced-motion`: 이 앱에는 애니메이션이 거의 없다(필요 시 상태 문구 전환만). 별도 처리 없음.

## 8. 핵심 로직 설계

### 그림 데이터 구조
- `cells`: 길이 256의 일차원 배열. 인덱스 `i = y * 16 + x`. 값은 `'#rrggbb'` 문자열 또는 `null`(투명).
- 상수: `SIZE = 16`. 편집기 상태(`createEditor()`가 돌려주는 객체)는 `getCells()`, `setCell(i, color) → boolean`, `clear() → 변경 수`, `beginStroke()` / `endStroke()`, `undo()`, `redo()`, `canUndo()`, `canRedo()`, `isEmpty()`, `serialize()`, `load(data) → boolean` 정도로 제한한다.
- `lineCells(x0, y0, x1, y1)`: 두 점 사이의 Bresenham 칸 목록(시작·끝 포함)을 `[x, y]` 배열로 돌려주는 순수 함수. 좌표는 정수, 범위 제한 없음. 범위 밖 걸러내기는 호출 쪽(`paintLine`)에서 한다.

### 칸 좌표 계산 (화면 크기가 달라져도 정확하게)
- `rect = canvas.getBoundingClientRect()`를 **이벤트마다** 읽는다(스크롤·리사이즈에 안전, 캐시하지 않거나 `ResizeObserver`/스크롤에서 갱신).
- `x = Math.floor((event.clientX - rect.left) / rect.width * 16)`, `y`도 같은 방식. 테두리가 `rect`에 포함되므로 CSS 테두리는 캔버스 `box-sizing: content-box` 바깥이 아닌 **캔버스를 감싸는 래퍼 요소**에 준다(캔버스 자체에 `border`를 주지 않아 좌표 어긋남을 막는다).
- 내부 해상도(픽셀 수)가 아니라 CSS 표시 크기를 기준으로 계산하므로 DPR·확대·리사이즈와 무관하게 정확하다.

### 입력 처리 흐름
1. `pointerdown`: 활성 포인터 확인 → 캡처 → `beginStroke()` → 현재 칸 칠함(스포이트면 집기만) → `last = [x, y]`.
2. `pointermove`(활성 포인터만): 합쳐진 샘플마다 `lineCells(last, 현재)`의 격자 안 칸을 칠하고 `last` 갱신. 렌더링은 rAF로 합친다.
3. 종료 이벤트: `endStroke()`(바뀐 칸이 있으면 기록 1건 추가) → 자동 저장 예약 → 버튼 활성/비활성 갱신.
4. 도구는 `'pencil' | 'eraser' | 'eyedropper'` 문자열, 색은 `selectedColor` 하나. 지우개는 `setCell(i, null)`.

### 되돌리기 기록 방식
- **획 단위 차분 기록**: 한 획 동안 바뀐 칸을 `{ index, before, after }` 목록으로 모은다. `endStroke()` 때 비어 있지 않으면 `undoStack`에 한 항목으로 push, `redoStack`은 비운다. 전체 256칸 스냅샷보다 작고 구현이 단순하다.
- `undo()`: 마지막 항목의 `before`를 복원하고 `redoStack`으로 옮긴다. `redo()`는 반대.
- 모두 지우기도 하나의 획(바뀐 칸만 기록)으로 취급하므로 **되돌릴 수 있다**. 이미 비어 있으면 기록하지 않는다.
- 스택 최대 100개(초과 시 가장 오래된 것 삭제). 키보드: `Ctrl/Cmd+Z`, `Ctrl/Cmd+Shift+Z`(또는 `Ctrl+Y`)를 `preventDefault`로 처리(P1에 포함, 수정키가 아닌 일반 키는 건드리지 않음).

### 자동 저장
- 키: `pixel-art:draft`. 값: `{ "v": 1, "cells": [...256], "color": "#rrggbb" }` JSON. 획 종료·모두 지우기·되돌리기·다시 실행 뒤 약 300ms 디바운스로 저장한다.
- 복원 시 `load()`가 형식을 검증한다: 배열 길이 256, 각 원소가 `null` 또는 `/^#[0-9a-f]{6}$/` 문자열. 하나라도 어긋나면 저장값을 버리고 빈 그림으로 시작한다. (사용자 입력이 아닌 저장소 값도 신뢰하지 않는다.)
- 되돌리기 기록은 저장하지 않는다(새로고침하면 되돌리기 내역은 비어 있음).
- 모든 `localStorage` 접근은 `try/catch`로 감싸며 실패해도 앱은 정상 동작한다.

### 보안·품질 메모
- 색 값은 항상 정규식으로 검증한 문자열만 `fillStyle`에 넣는다. DOM에는 `textContent`로만 쓴다.
- 파일 이름의 시각 문자열은 숫자만 사용한다.

## 9. 블로그 삽입 계획 (Embed 단계)

**제안: 2048과 같은 카드 + iframe 미리보기**
- **위치**: `index.html`의 `<section class="app-cards">` 안, 2048 `<article class="app-card">` 뒤에 같은 마크업의 카드를 하나 더 둔다. `blog.js`는 건드리지 않는다.
- **제목**: 픽셀 아트 에디터
- **설명**: "16×16 격자에 도트를 찍어 그림을 그리고 PNG로 저장하는 에디터. 색상 팔레트와 되돌리기를 지원합니다."
- **링크**: 카드 제목과 "그려 보기" 링크(2048은 "플레이하기") → `apps/pixel-art/index.html`
- **미리보기**: `<iframe src="apps/pixel-art/index.html?preview" title="픽셀 아트 에디터 미리보기" loading="lazy" tabindex="-1">`를 기존 `.app-card-preview`(160×160) 안에 둔다.
- **`?preview` 모드 내용**
  - 헤더, 도구, 팔레트, 동작·저장 영역, 상태 문구를 모두 숨기고 **캔버스만** 보여 준다(`.preview` 클래스, 2048과 동일 방식).
  - 고정된 예시 그림(예: 하트와 별 도트, 5~6색 사용)을 `main.js`에 문자열 지도로 두고 그린다. 격자선은 켠 상태.
  - 입력(포인터·키보드)을 받지 않고, **`localStorage`를 읽지도 쓰지도 않는다**(자동 저장 초안을 덮어쓰거나 불러오지 않음). 테마 값 읽기는 `<head>` 스크립트만 한다. 2048 리뷰에서 확인한 "미리보기가 저장값에 영향을 주지 않음" 기준을 그대로 적용한다.
  - 카드 안에서 160×160에 맞도록 `.preview` 때 앱 여백을 줄이고 캔버스가 폭을 꽉 채우게 한다.
- **이유**: 실제 화면과 항상 일치하고 테마(캔버스 바탕은 고정)에 따라 UI 색이 자연스럽게 바뀐다. 정적 이미지는 버전이 어긋날 수 있다.
- **대안**: 정적 SVG(`images/pixel-art-preview.svg`) — 가볍지만 예시 그림을 따로 관리해야 한다. iframe에 문제가 있을 때의 후순위 안.
- **CSS 영향**: 카드가 두 개가 되므로 `.app-card + .app-card { margin-top: 1rem; }` 같은 간격 규칙을 `css/style.css`에 추가한다(Embed 단계에서만 블로그 파일 수정).

## 10. 검증 체크리스트 (Review, 브라우저에서 확인)

**그리기**
- [ ] 격자가 16×16으로 보이고 정사각형이다 (가로세로 비 1:1)
- [ ] 한 번 누르면 정확히 그 칸 한 개만 선택 색으로 칠해진다 (네 모서리 칸, 가운데 칸 모두)
- [ ] 드래그하면 칠한 칸이 이어진다. 가로·세로·대각선으로 매우 빠르게 움직여도 칸이 끊기지 않는다 (이벤트를 일부러 멀리 떨어진 좌표로 발생시켜 확인)
- [ ] 같은 칸 위에서 이벤트가 반복돼도 되돌리기 기록이 늘지 않는다 (한 획 = 되돌리기 1번)
- [ ] 격자 밖으로 나갔다 들어와도 선이 이어지고 바깥에서는 아무것도 칠해지지 않는다 (가장자리 칸 포함)
- [ ] 마우스(`pointerType: 'mouse'`), 터치(`'touch'`), 펜(`'pen'`) 입력이 모두 동작한다. 두 번째 포인터와 마우스 오른쪽 버튼은 무시된다
- [ ] 터치로 그리는 동안 페이지가 스크롤·확대되지 않는다 (`touch-action: none`, 실제 기기 체감은 미확인으로 기록 가능)
- [ ] 캔버스 크기를 바꿔도(375px, 320px, 데스크톱 창 크기 변경) 누른 위치와 칠해진 칸이 일치한다

**도구·팔레트**
- [ ] 팔레트 16색이 표의 값과 일치하고, 클릭하면 선택 링이 이동하며 선택 색 텍스트가 갱신된다
- [ ] 지우개로 칠한 칸이 투명(체크무늬)으로 돌아간다. 스포이트가 색을 집고 연필로 돌아가며, 투명 칸이면 지우개로 전환된다
- [ ] 사용자 지정 색이 선택 색으로 반영되고 `#rrggbb` 소문자로 저장된다
- [ ] 격자선 토글이 화면에만 적용되고 PNG에는 영향이 없다
- [ ] 되돌리기·다시 실행이 획 단위로 동작하고, 모두 지우기도 되돌릴 수 있다. 새 획을 그리면 다시 실행 기록이 비워진다
- [ ] 라이트/다크 전환 시 UI는 바뀌지만 **그려 둔 그림의 색과 캔버스 바탕은 바뀌지 않는다**

**PNG 저장**
- [ ] `PNG 저장`을 누르면 `pixel-art-YYYYMMDD-HHmmss.png` 파일이 실제로 내려받아진다
- [ ] 파일 크기(픽셀)가 **512×512**이다. 확인 방법: 내려받은 파일의 처음 24바이트에서 PNG 시그니처와 IHDR의 폭·높이를 읽거나, 파일을 `Image`/`createImageBitmap`으로 불러 `naturalWidth/Height`를 확인한다. 자동 확인이 어려우면 다운로드 폴더의 실제 파일을 열어 확인한다
- [ ] **픽셀 값 확인**: 테스트용 그림(네 모서리, 가운데, 서로 다른 색 몇 칸, 지운 칸)을 그린 뒤, PNG를 디코드해 오프스크린 캔버스에 그리고 `getImageData`로 각 칸의 중심 픽셀(`x*32+16, y*32+16`)과 칸의 네 귀퉁이 픽셀이 기대한 `#rrggbb` / 알파 값과 일치하는지 비교한다. 칸 경계(`x*32-1`과 `x*32`)에서 색이 정확히 갈리고 중간색(보간)이 없는지 확인한다
- [ ] 칠하지 않은 칸의 알파가 0(투명)이고, 체크무늬·격자선이 PNG에 들어가지 않았다
- [ ] 격자선이 켜진 상태/꺼진 상태에서 저장한 PNG가 동일하다
- [ ] 아무것도 그리지 않고 저장하면 파일이 생기지 않고 안내 문구가 나온다
- [ ] 저장 후 상태 문구가 보이고, `details` 대체 안내의 이미지가 선명한(흐리지 않은) 도트로 보인다
- [ ] 가능하면 `a.click` 또는 `URL.createObjectURL`을 가로채 Blob의 `type`(`image/png`)과 크기를 기록한다. 모바일 실기기 저장은 에뮬레이션으로 확인할 수 없으므로 **미확인**으로 적는다

**저장·복원**
- [ ] 그림을 그리고 새로고침하면 그림과 선택 색이 복원된다. 되돌리기 기록은 비어 있다
- [ ] 저장값을 손상시키면(길이 불일치, 잘못된 색 문자열, JSON 아님) 빈 그림으로 시작하고 오류가 없다
- [ ] `localStorage` 접근이 예외를 던지는 환경에서도 그리기·저장이 오류 없이 동작한다
- [ ] 테스트 후 `pixel-art:draft`, `theme` 값을 정리한다

**화면**
- [ ] 375px와 320px에서 가로 스크롤이 없고(`scrollWidth`), 캔버스가 정사각형이다
- [ ] 모든 버튼·견본·링크의 크기가 44×44px 이상, 글자는 16px 이상이다 (실측)
- [ ] 라이트/다크 모두 UI 글자 대비비 4.5:1 이상, 팔레트 견본 윤곽과 캔버스 테두리가 배경과 구분된다 (검정·남색 견본이 다크에서 보이는지 포함, 계산값으로 기록)
- [ ] 흰색(`#ffffff`) 칸과 투명 칸이 체크무늬 위에서 구분된다
- [ ] 720px 이상에서 2열 배치가 올바르다
- [ ] 저장된 테마가 적용되고 깜빡임이 없다 (`<head>` 인라인 스크립트가 CSS보다 먼저 실행되는 구조 확인)
- [ ] 접근성: 캔버스 `role="img"` 안에 컨트롤이 없고, 토글 버튼에 `aria-pressed`, 팔레트에 선택 상태 속성이 있다
- [ ] 콘솔 에러 없음 (일반 모드, 미리보기 모드 모두)

**삽입 (Embed)**
- [ ] 블로그 메인에 카드가 2048 카드 아래에 표시되고 두 테마 모두에서 어울린다
- [ ] 카드(미리보기, 제목, 링크)를 누르면 `apps/pixel-art/index.html`로 이동한다
- [ ] `?preview`에서 입력이 무시되고 `localStorage` 값(`pixel-art:draft`)을 읽지도 바꾸지도 않는다
- [ ] 기존 글 목록과 2048 카드가 그대로 동작한다

## 11. 미정 사항 (사용자에게 질문)
1. **PNG 출력 크기**를 512×512(32배) 고정으로 할까요, 크기를 고르게 할까요(예: 16/128/512)? — **권장: 512×512 고정.** 선택 UI가 없어 단순하고 대부분의 용도에 충분합니다.
2. **PNG 배경**을 투명으로만 할까요, 흰 배경 선택도 둘까요? — **권장: 투명 고정.** 필요하면 나중에 옵션으로 추가합니다.
3. **모두 지우기**에 확인창을 띄울까요? — **권장: 확인창 없이 즉시 지우고 되돌리기로 복구 가능**하게 합니다(2048의 새 게임과 같은 방침).
4. **진행 중인 그림 자동 저장**을 이번 범위에 넣을까요? — **권장: 포함(P1).** 실수로 새로고침해도 그림을 잃지 않습니다. 빼면 새로고침 시 빈 화면으로 시작합니다.
5. **키보드로 그리기**(방향키로 칸 이동, 스페이스로 칠하기)를 넣을까요? — **권장: 이번에는 제외.** 마우스·터치 중심 앱이며 구현 범위가 커집니다. 대신 도구·팔레트·저장은 모두 키보드로 조작 가능하게 합니다. 접근성을 중시하면 후속 작업으로 분리합니다.
6. **블로그 카드 미리보기**는 2048처럼 iframe으로 할까요, 정적 SVG로 할까요? — **권장: iframe(`?preview`).**
7. **격자 크기**를 16×16 고정으로 둘까요? — **권장: 고정.** 요청 사양이 16×16이고 크기 변경은 데이터·좌표·PNG 로직을 모두 복잡하게 만듭니다.
