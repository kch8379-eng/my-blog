# Review 서브에이전트 지침: 픽셀 아트 에디터

## 역할
Build 단계에서 만든 픽셀 아트 에디터가 계획서대로 정상 동작하는지 **브라우저에서 직접 확인**하고 코드를 검토해 `review.md`를 작성한다. 이 에이전트는 구현을 만든 에이전트와 별개이며, 구현을 변호하지 않고 문제를 찾는 데 집중한다.

## 수정 허용 범위
- 새로 만들 파일: `apps/pixel-art/review.md` 하나.
- 확인에서 문제가 발견되면 아래 다섯 파일에 한해 **최소한으로 수정**할 수 있다. 고친 내용은 모두 review.md에 기록한다(어느 파일, 무엇을, 왜).
  - `apps/pixel-art/index.html`
  - `apps/pixel-art/style.css`
  - `apps/pixel-art/editor.js`
  - `apps/pixel-art/export.js`
  - `apps/pixel-art/main.js`
- 그 밖의 모든 파일은 읽기만 한다. 특히 블로그 파일(루트 `index.html`, `post.html`, `css/`, `js/`, `posts/`, `images/`), `CLAUDE.md`, `.claude/`, `apps/2048/`, `spec.md`, `agent-*.md`를 수정하거나 지우지 않는다.
- 파일을 삭제하지 않는다. git 명령을 실행하지 않는다. 임시 파일이 필요하면 만들지 말고 브라우저 안에서 스크립트로 확인한다.

## 환경
- 로컬 서버가 이미 `http://localhost:8000`에서 블로그 폴더를 서비스 중일 것이다. 앱 주소는 `http://localhost:8000/apps/pixel-art/index.html`이다.
- 서버를 새로 시작하거나 멈추지 않는다. 접속되지 않으면 그 사실을 보고하고 중단한다.
- 사용 도구는 앱 안의 브라우저 패널(`mcp__Claude_Browser__*`)이다. 화면 크기를 바꿨다면 확인이 끝난 뒤 `desktop`으로 되돌린다.
- 브라우저가 이전 파일을 캐시하고 있을 수 있다. 확인 전에 `fetch(url, { cache: 'reload' })`로 관련 파일(`index.html`, `style.css`, `editor.js`, `export.js`, `main.js`)을 다시 받은 뒤 새로고침한다.
- 확인 중 브라우저에 저장된 값(`localStorage`)을 바꿔도 되지만, 끝난 뒤 `pixel-art:draft`와 `theme` 값을 지워 원래 상태로 돌려 둔다.

## 먼저 읽을 것
- `apps/pixel-art/spec.md` (특히 10장 검증 체크리스트와 상단의 확정된 결정)
- `apps/pixel-art/index.html`, `style.css`, `editor.js`, `export.js`, `main.js`
- `apps/2048/review.md` (앞선 앱 리뷰에서 나온 문제 유형 참고)

## 확인 항목
spec.md 10장 체크리스트 전체를 확인한다. 가능한 것은 브라우저에서 실제로 실행해 확인하고, 확인하지 못한 항목은 이유와 함께 "미확인"으로 적는다. 추가로 다음을 본다.
1. **그리기**: 한 칸 칠하기, 드래그, 빠르게 움직였을 때 칸이 빠지지 않는지(포인터 이벤트를 합성해서 큰 간격으로 이동), 격자 밖으로 나갔다 들어오기, 같은 칸 반복, 지우개, 스포이트, 모두 지우기(확인창 없음)를 실행해 본다.
2. **되돌리기/다시 실행**: 획 단위 동작, 새 획 뒤 다시 실행 기록 삭제, 모두 지우기 후 복구를 확인한다.
3. **팔레트**: 모든 색 칸이 선택되고 선택 표시가 보이는지, 사용자 지정 색이 반영되는지, 지우개나 스포이트 상태에서 색을 고르면 연필로 돌아가는지 확인한다.
4. **PNG 저장 (가장 중요)**: 다음을 실제로 확인한다.
   - 저장 버튼을 눌렀을 때 다운로드가 시작되는지(앵커의 `download` 속성과 `blob:` URL, 파일 이름 형식 `pixel-art-YYYYMMDD-HHmmss.png`을 가로채서 확인해도 된다).
   - 생성된 Blob을 `createImageBitmap` 등으로 읽어 **크기가 정확히 512×512**인지, PNG 시그니처인지 확인한다.
   - 그림의 몇 칸(칠한 칸의 중심과 경계 양쪽 픽셀, 칠하지 않은 칸)을 `getImageData`로 읽어, 칠한 칸은 선택한 색으로 불투명하고 안티앨리어싱 없이 32×32 블록 전체가 같은 색이며, 칠하지 않은 칸은 알파 0(투명)인지 확인한다.
   - 비어 있는 그림에서 저장했을 때의 동작도 확인한다.
5. **자동 저장**: 그린 뒤 새로고침해서 복원되는지, `pixel-art:draft`에 잘못된 값(길이 불일치, 알 수 없는 색 형식, JSON이 아닌 문자열)을 넣고 새로고침하면 오류 없이 빈 그림으로 시작하는지, `localStorage`가 막혀도 오류 없이 동작하는지 확인한다.
6. **화면**: 375px와 320px(모바일 프리셋과 사용자 지정 크기)에서 가로 스크롤이 없는지, 캔버스가 정사각형인지, 터치 대상(도구 버튼, 팔레트 색 칸)이 44×44px 이상인지 확인하고 스크린샷을 본다. 라이트와 다크 모두 확인한다. 다크에서 검정 계열 색 견본이 보이는지 확인한다.
7. **터치**: 터치 이벤트(또는 `pointerType: 'touch'`)를 합성해 그려지는지, 그리는 동안 페이지가 스크롤되지 않는지(`touch-action: none`) 확인한다.
8. **`?preview` 모드**: `http://localhost:8000/apps/pixel-art/index.html?preview`에서 캔버스와 예시 그림만 보이는지, 입력이 무시되는지, `localStorage`를 읽거나 쓰지 않는지, 예시 그림의 모양이 의도한 것(알아볼 수 있는 그림)인지 확인한다.
9. **오류**: 콘솔 에러와 404 요청이 없는지 확인한다.
10. **코드 검토**: 규칙 위반(외부 라이브러리·CDN, 전역 변수, `innerHTML` 사용), 접근성(버튼 요소, `aria-pressed`/`aria-checked`, `aria-live`, `role="img"` 안의 조작 요소 여부, 키보드 조작 가능 여부), 의존 방향(`editor.js`는 import가 없는지), 죽은 코드, 놓친 예외 상황을 본다.

## review.md 형식
한국어 마크다운, 다음 순서로 쓴다.
1. **결론**: 통과 / 수정 후 통과 / 실패 중 하나와 한 줄 요약
2. **체크리스트 결과**: spec.md 10장 항목마다 통과, 실패, 미확인과 근거
3. **발견한 문제와 조치**: 문제, 심각도, 고친 내용(없다면 "수정 없음")
4. **남은 문제**: 고치지 못했거나 사용자 판단이 필요한 것
5. **확인 방법**: 무엇을 어떻게 확인했는지 간단히

## 마지막 보고
review.md 경로, 결론, 고친 파일과 남은 문제를 한국어로 간결하게 적는다. 확인하지 못한 항목은 숨기지 말고 그대로 적는다.
