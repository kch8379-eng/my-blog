# Plan 서브에이전트 지침: 픽셀 아트 에디터

## 역할
픽셀 아트 에디터 웹앱의 **구현 계획서**를 작성한다. 코드는 작성하지 않는다.

## 수정 허용 범위
- 새로 만들 파일은 `apps/pixel-art/spec.md` 하나뿐이다.
- 다른 모든 파일은 읽기만 한다. 수정, 삭제, 이름 변경을 하지 않는다.
- 명령 실행이나 서버 시작을 하지 않는다.

## 먼저 읽을 것
- `CLAUDE.md` (프로젝트 규칙, 특히 웹앱 규칙)
- `apps/2048/spec.md`, `apps/2048/review.md` (같은 사이클로 만든 앞선 앱. 계획서 형식, 테마 처리, 미리보기 모드, 카드 삽입 방식, 리뷰에서 나온 교훈을 참고)
- `apps/2048/index.html`, `apps/2048/style.css`, `apps/2048/main.js` (구현 스타일 참고용)
- `index.html`, `css/style.css` (블로그 메인의 앱 카드 구조 파악용)

## 사용자 요청
> 픽셀 아트 에디터를 만들어줘. 16x16 격자에 도트를 찍어서 그림을 그리고, 완성하면 PNG로 저장할 수 있게 해줘. 색상 팔레트도 넣어줘.

## 제약
- HTML, CSS, JavaScript만 사용한다. 이 앱은 `/apps/pixel-art/` 안에서 자체 완결된다.
- 외부 라이브러리 사용을 최소화한다. PNG 저장은 브라우저 기본 기능(`canvas`의 `toBlob` 등)으로 해결할 수 있는지 검토하고, 가능하면 라이브러리를 쓰지 않는다.
- 모바일에서도 사용할 수 있어야 한다. 마우스와 터치(손가락 드래그)로 모두 그릴 수 있게 계획한다.
- 다크 모드를 지원하는 블로그와 어울리는 화면을 설계한다. 단, 사용자가 고른 그림의 색은 테마에 따라 바뀌지 않아야 한다.
- 2048 앱과 같은 파일 구조 원칙을 따른다(로직과 화면 처리를 분리하는 등).

## spec.md에 반드시 포함할 내용
1. **개요**: 어떤 앱인지 두세 문장
2. **기능 목록**: 필수(16×16 격자, 클릭·드래그로 칠하기, 색상 팔레트, PNG 저장, 전체 지우기)와 선택(지우개, 되돌리기, 스포이트, 격자선 켜고 끄기, 사용자 지정 색 선택, 진행 중인 그림 자동 저장 등)을 구분하고 우선순위를 매긴다.
3. **그리기 동작**: 한 칸 칠하기, 드래그로 이어 칠하기(빠르게 움직여도 칸이 빠지지 않게 하는 방법), 같은 칸 반복 처리, 격자 밖으로 나갔을 때 처리, 마우스·터치·펜 입력 통합(Pointer Events 등)
4. **색상 팔레트**: 기본 색 목록(개수와 구체적인 색 값, 라이트/다크 어디서나 구분되는지), 선택 표시 방식, 사용자 지정 색 지원 여부
5. **PNG 저장**: 출력 해상도(원본 16×16을 몇 배로 키울지, 확대 시 픽셀이 흐려지지 않게 하는 방법), 배경을 투명으로 할지 흰색으로 할지, 파일 이름, 다운로드 방식(`a[download]`), 모바일 브라우저에서의 동작과 한계
6. **파일 구조**: `apps/pixel-art/` 안의 파일과 각 파일의 역할
7. **화면 설계**: 레이아웃(글로 설명), 격자 표시 방식(`canvas` 또는 DOM 중 선택과 이유), 팔레트와 도구 배치, 모바일 폭(375px) 배치, 터치 대상 크기
8. **핵심 로직 설계**: 그림 데이터 구조, 칸 좌표 계산(화면 크기가 달라져도 정확하게), 입력 처리, 되돌리기를 넣는다면 기록 방식
9. **블로그 삽입 계획**: 2048 카드와 같은 방식으로 `index.html`에 넣을 카드의 제목, 설명, 미리보기 방식 제안(`?preview` 모드의 내용 포함)과 이유
10. **검증 체크리스트**: Review 단계에서 브라우저로 확인할 항목. PNG 저장은 실제 다운로드되는 파일의 크기와 픽셀 값까지 확인할 방법을 적는다.
11. **미정 사항**: 사용자에게 물어봐야 할 결정이 있으면 질문 형태로 적고, 각 질문마다 권장안을 함께 적는다.

## 형식
- 한국어, 마크다운. 간결하게 쓴다.
- 마지막 보고에는 spec.md 경로와 핵심 결정 3~5개를 요약한다.
