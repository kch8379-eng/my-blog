# 2048 Review

## 1. 결론
**수정 후 통과** (Embed 항목 제외). 게임 규칙, 점수판, 입력, 화면, `?preview` 모드는 모두 브라우저에서 확인해 통과했다. 접근성 구조 문제 1건을 고쳤다. 블로그 메인의 카드 삽입(Embed 단계)은 이번 범위 밖이라 확인하지 않았다.

## 2. 체크리스트 결과 (spec.md 9장)

**규칙/로직**
- [통과] 시작 시 타일 2개, 값은 2 또는 4: 새 게임마다 타일 2개, 값 2 확인.
- [통과] 네 방향 이동·합치기: 샘플 보드에서 left/right/up/down 결과가 모두 기대와 일치하고 원본 보드는 변하지 않음.
- [통과] 한 이동에 한 번만 합침: `[2,2,2,2]`→`[4,4,0,0]`, `[4,2,2,0]`→`[4,4,0,0]`, `[2,2,2,0]`→`[4,2,0,0]`, `[2,0,2,4]`→`[4,4,0,0]`, `[2,2,4,0]`→`[4,4,0,0]`, `[2,2,4,4]`→`[4,8,0,0]`.
- [통과] 변화 없는 이동: `moved=false`, 새 타일 없음, 점수 그대로, 되돌리기 기록 안 남음(화면과 로직 모두 확인).
- [통과] 새 타일 분포: 20,000회 시뮬레이션에서 2가 18,054회, 4가 1,946회(약 9.03:1). 빈 칸이 아닌 곳에 생성된 경우 0회.
- [통과] 2048 달성 안내는 한 번만, "계속하기"로 이어서 플레이: 시드를 고정한 실제 화면에서 940수 만에 "2048 달성!" 오버레이가 뜸. 오버레이 중 키 입력은 무시됨. "계속하기" 후 플레이를 이어가도 안내가 다시 뜨지 않음.
- [통과] 가득 차도 합칠 쌍이 있으면 게임 오버 아님: 가로 쌍 보드, 세로 쌍 보드 모두 `false`. 빈 칸이 있는 보드도 `false`.
- [통과] 합칠 수 없이 가득 차면 게임 오버: 체커보드 보드 `true`. 실제 화면에서 "게임 오버" 오버레이와 "다시 하기" 버튼 표시, 포커스가 버튼으로 이동.

**점수판**
- [통과] 점수 증가와 `+N` 표시: 합칠 때 `+4`가 표시되고 약 0.5초 후 사라짐.
- [통과] 최고 점수 갱신과 유지: 점수 초과 즉시 `2048:best`에 저장, 새로고침 후에도 유지.
- [통과] 새 게임은 현재 점수만 0으로: 최고 점수는 유지됨.
- [통과] `localStorage` 차단 시 동작: `getItem`/`setItem`이 예외를 던지도록 바꾼 환경에서 오류 없이 플레이되고 최고 점수는 메모리 값으로 갱신됨.

**입력**
- [통과] 방향키와 WASD: 8개 키 모두 `preventDefault` 처리되어 이동하며, 관계없는 키(Q)는 무시. 되돌리기는 1단계이고 점수가 함께 복원되며 연속 되돌리기는 불가.
- [통과] 스와이프 4방향과 탭 무시: 포인터 이벤트로 상하좌우 이동 확인. 탭(0px)과 10px 이동은 무시됨.
- [통과] 스와이프 중 스크롤 방지: `touchmove`가 `preventDefault` 처리되고 `touch-action: none` 적용됨. (실제 터치 기기에서의 체감은 미확인)

**화면**
- [통과] 타일 글자 대비비(라이트/다크 모두 4.5:1 이상). 계산값 최저는 라이트 64 타일 4.73, 다크 32 타일 4.94. 그 밖에 힌트 글자 6.00/7.11, 점수 라벨 5.59/6.47, 기본 버튼 6.16/8.49, 링크 6.16/8.33.
- [통과] 저장된 테마 적용과 깜빡임 방지: `localStorage['theme']`가 `light`/`dark`일 때 앱에 반영됨. `<head>` 인라인 스크립트가 CSS보다 먼저 실행되는 구조. (깜빡임 자체를 눈으로 잡아내는 측정은 하지 못함)
- [통과] 375px: 가로 스크롤 없음(scrollWidth 375), 보드 343×343 정사각형. 320px에서도 가로 스크롤 없고 보드 288×288.
- [통과] 터치 대상과 글자 크기: 버튼 높이 44px(폭 167.5px), "← 블로그" 링크 68.8×44px, 화면 글자 최소 16px.
- [미확인] `prefers-reduced-motion` 동작: 브라우저 패널에서 이 설정을 켤 수 없었음. 코드상 `motionQuery.matches`이면 타일 애니메이션을 건너뛰고 CSS도 `.score-gain` 전환을 끔.
- [통과] 콘솔 에러 없음: 일반 모드, 미리보기, 수정 후 모두 콘솔 메시지 0건.

**삽입 (Embed)**
- [미확인] 블로그 메인 카드, 카드 클릭 이동, 기존 글 목록 동작: Embed 단계는 이번 Review의 대상이 아니고 블로그 파일은 읽기만 하는 범위라 확인하지 않음. 미리보기 iframe의 영향 부분은 아래 `?preview` 확인으로 갈음.

**`?preview` 모드 (agent-review 추가 항목)**
- [통과] 헤더, 점수판, 안내 문구가 숨겨지고 보드만 보임. 고정 예시 배치(2~2048)가 라이트/다크에서 올바르게 표시됨.
- [통과] 방향키, WASD, 스와이프 입력이 모두 무시됨. 미리보기에서 `2048:best`(777)와 `theme` 값을 읽거나 쓰지 않음(값 그대로 유지).

## 3. 발견한 문제와 조치

| # | 문제 | 심각도 | 조치 |
|---|---|---|---|
| 1 | `#board`에 `role="img"`가 있는데 그 안에 게임 오버/승리 `role="dialog"`와 버튼이 들어 있음. `img` 역할의 자식은 보조기기에서 표현만 되는 요소로 취급되어, 오버레이 버튼이 스크린 리더에서 가려질 수 있다. | 낮음~중간 (접근성) | 수정함. 아래 참고. |

**수정 내역**
- `apps/2048/index.html`: `#board`에서 `role="img"`와 `aria-label`을 제거하고, 타일 레이어 `#tile-layer`에 `role="img" aria-label="2048 보드"`를 옮김(기존 `aria-hidden` 제거). 칸 레이어 `#cell-layer`는 `aria-hidden="true"` 유지. 이유: 오버레이가 이미지 역할 밖의 형제 요소가 되도록 하기 위함.
- `apps/2048/main.js`: `renderBoard`의 `boardEl.setAttribute('aria-label', ...)`를 `tileLayer.setAttribute('aria-label', ...)`로 변경. 이유: 위 구조 변경에 맞춰 보드 상태 설명이 같은 요소에 들어가게 함.
- 수정 후 확인: 보드 크기(정사각형), 타일 렌더, 이동 후 aria-label 갱신, 오버레이가 이미지의 형제로 나타남, 콘솔 에러 0건.
- `style.css`, `game.js`는 수정하지 않음.

**코드 검토 결과 (수정 불필요)**
- 외부 라이브러리·CDN·웹 폰트 없음, 전역 변수 없음(ES 모듈), `innerHTML` 미사용(`textContent`와 `replaceChildren`만 사용).
- 점수 값만 `aria-live="polite"`, 버튼은 모두 `<button type="button">`.
- 죽은 코드 없음.

## 4. 남은 문제
- 승리(2048 달성) 이동이 동시에 게임 오버가 되는 경우 "게임 오버"만 표시되고 승리 안내는 나오지 않는다. 극히 드문 경우라 그대로 두었다. 사용자 판단 필요 없음.
- 2048 달성 직후 되돌리기를 하면 `won`이 함께 되돌려져, 다시 2048을 만들 때 안내가 한 번 더 뜬다. 계획서의 "한 판에 한 번" 문구와 엄밀히는 다르지만 되돌리기의 자연스러운 결과로 보고 수정하지 않았다.
- 비활성 "되돌리기" 버튼의 글자는 `opacity: 0.6`이 적용되어 대비비가 4.5:1에 못 미칠 수 있다. 비활성 컨트롤은 WCAG 대비 기준 예외라 두었다.
- 미확인: `prefers-reduced-motion`, 실제 터치 기기 스와이프, 블로그 카드 삽입(Embed), 애니메이션의 시각적 품질(스크린샷으로는 정지 화면만 확인).

## 5. 확인 방법
- 앱: `http://localhost:8000/apps/2048/index.html`, 미리보기: `?preview`. 서버는 시작하거나 멈추지 않음.
- 로직: 브라우저 콘솔에서 `game.js`를 동적 `import`해 `slideLine`, `moveBoard`, `isGameOver`, `createGame`을 직접 호출.
- 입력: `KeyboardEvent`와 `PointerEvent`/`TouchEvent`를 만들어 페이지에 디스패치.
- 승리/게임 오버: 시드 고정 난수와 간단한 휴리스틱으로 승리하는 수순을 찾은 뒤, 같은 출처 iframe에 앱을 불러 `Math.random`을 고정하고 그 수순을 키 이벤트로 재생해 실제 화면과 오버레이를 확인.
- 화면: 375px(모바일 프리셋)와 320px에서 크기·가로 스크롤·버튼 크기 측정과 스크린샷 확인, 라이트/다크 전환, 대비비는 실제 계산된 색으로 직접 계산.
- 오류: 콘솔 메시지와 네트워크 요청 확인(404 없음).
- 정리: 화면 크기를 desktop으로 복원하고 `localStorage`의 `2048:best`, `theme`를 삭제.
