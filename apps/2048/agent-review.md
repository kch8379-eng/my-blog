# Review 서브에이전트 지침: 2048 게임

## 역할
Build 단계에서 만든 2048 앱이 계획서대로 정상 동작하는지 **브라우저에서 직접 확인**하고 코드를 검토해 `review.md`를 작성한다. 이 에이전트는 구현을 만든 에이전트와 별개이며, 구현을 변호하지 않고 문제를 찾는 데 집중한다.

## 수정 허용 범위
- 새로 만들 파일: `apps/2048/review.md` 하나.
- 확인에서 문제가 발견되면 아래 네 파일에 한해 **최소한으로 수정**할 수 있다. 고친 내용은 모두 review.md에 기록한다(어느 파일, 무엇을, 왜).
  - `apps/2048/index.html`
  - `apps/2048/style.css`
  - `apps/2048/game.js`
  - `apps/2048/main.js`
- 그 밖의 모든 파일은 읽기만 한다. 특히 블로그 파일(루트 `index.html`, `post.html`, `css/`, `js/`, `posts/`, `images/`), `CLAUDE.md`, `.claude/`, `spec.md`, `agent-*.md`를 수정하거나 지우지 않는다.
- 파일을 삭제하지 않는다. git 명령을 실행하지 않는다. 임시 파일이 필요하면 만들지 말고 브라우저 안에서 스크립트로 확인한다.

## 환경
- 로컬 서버가 이미 `http://localhost:8000`에서 블로그 폴더를 서비스 중일 것이다. 앱 주소는 `http://localhost:8000/apps/2048/index.html`이다.
- 서버를 새로 시작하거나 멈추지 않는다. 접속되지 않으면 그 사실을 보고하고 중단한다.
- 사용 도구는 앱 안의 브라우저 패널(`mcp__Claude_Browser__*`)이다. 화면 크기를 바꿨다면 확인이 끝난 뒤 `desktop`으로 되돌린다.
- 확인 중 브라우저에 저장된 값(`localStorage`)을 바꿔도 되지만, 끝난 뒤 `2048:best`와 `theme` 값을 지워 원래 상태로 돌려 둔다.

## 먼저 읽을 것
- `apps/2048/spec.md` (특히 9장 검증 체크리스트와 상단의 확정된 결정)
- `apps/2048/index.html`, `style.css`, `game.js`, `main.js`

## 확인 항목
spec.md 9장 체크리스트 전체를 확인한다. 가능한 것은 브라우저에서 실제로 실행해 확인하고, 확인하지 못한 항목은 이유와 함께 "미확인"으로 적는다. 추가로 다음을 본다.
1. **로직**: `game.js`가 모듈로 불러와지면 브라우저 콘솔에서 `slideLine`과 `move`를 직접 호출해, 예시 `[2,2,2,2]`, `[4,2,2,0]`, `[2,2,2,0]`, `[2,0,2,4]`와 네 방향 이동, 변화 없는 이동, 게임 오버 판정(가득 찬 보드, 합칠 수 있는 쌍이 있는 보드)을 검증한다.
2. **입력**: 키보드 이벤트를 만들어 방향키와 WASD로 이동되는지, 되돌리기(1단계, 점수 복원)가 동작하는지 확인한다. 스와이프는 터치 이벤트를 만들어 4방향과 탭 무시를 확인한다.
3. **화면**: 375px(모바일 프리셋)에서 가로 스크롤이 없는지, 보드가 정사각형인지, 터치 대상 44px 이상인지 확인하고 스크린샷을 본다. 라이트와 다크 모두 확인한다. 타일 색 대비비는 계산해서 4.5:1 미만인 쌍을 찾는다.
4. **`?preview` 모드**: `http://localhost:8000/apps/2048/index.html?preview`에서 보드만 보이는지, 키 입력이 무시되는지, 최고 점수를 읽거나 쓰지 않는지 확인한다.
5. **오류**: 콘솔 에러와 404 요청이 없는지 확인한다.
6. **코드 검토**: 규칙 위반(외부 라이브러리·CDN, 전역 변수, `innerHTML` 오용), 접근성(`aria-live`, 버튼 요소, 대체 텍스트), 죽은 코드, 놓친 예외 상황을 본다.

## review.md 형식
한국어 마크다운, 다음 순서로 쓴다.
1. **결론**: 통과 / 수정 후 통과 / 실패 중 하나와 한 줄 요약
2. **체크리스트 결과**: spec.md 9장 항목마다 통과, 실패, 미확인과 근거
3. **발견한 문제와 조치**: 문제, 심각도, 고친 내용(없다면 "수정 없음")
4. **남은 문제**: 고치지 못했거나 사용자 판단이 필요한 것
5. **확인 방법**: 무엇을 어떻게 확인했는지 간단히

## 마지막 보고
review.md 경로, 결론, 고친 파일과 남은 문제를 한국어로 간결하게 적는다. 확인하지 못한 항목은 숨기지 말고 그대로 적는다.
