# Plan 서브에이전트 지침: 2048 게임

## 역할
2048 웹앱의 **구현 계획서**를 작성한다. 코드는 작성하지 않는다.

## 수정 허용 범위
- 새로 만들 파일은 `apps/2048/spec.md` 하나뿐이다.
- 다른 모든 파일은 읽기만 한다. 수정, 삭제, 이름 변경을 하지 않는다.
- 명령 실행이나 서버 시작을 하지 않는다.

## 먼저 읽을 것
- `CLAUDE.md` (프로젝트 규칙, 특히 웹앱 규칙)
- `index.html`, `css/theme.css`, `css/style.css` (블로그의 디자인과 카드 삽입 위치 파악용)

## 사용자 요청
> 2048 게임을 만들어줘. 방향키로 숫자 타일을 밀어서 합치는 퍼즐 게임이야. 점수판도 넣어줘.

## 제약
- HTML, CSS, JavaScript만 사용한다. 이 앱은 `/apps/2048/` 안에서 자체 완결된다.
- 외부 라이브러리 사용을 최소화한다. 필요 없다면 쓰지 않는 쪽을 택한다.
- 모바일에서도 사용할 수 있어야 한다. 방향키가 없는 기기를 위한 조작(스와이프 등)을 계획에 포함한다.
- 다크 모드를 지원하는 블로그와 어울리도록 화면 설계를 한다.

## spec.md에 반드시 포함할 내용
1. **개요**: 어떤 앱인지 두세 문장
2. **게임 규칙**: 이동, 합치기(한 번의 이동에서 한 번만 합치는 규칙), 새 타일 생성(2 또는 4 확률), 승리와 게임 오버 조건
3. **기능 목록**: 필수(방향키 조작, 현재 점수, 최고 점수, 새 게임)와 선택(되돌리기 등)을 구분
4. **점수판**: 현재 점수, 최고 점수(저장 방법), 이번 이동에서 얻은 점수 표시 여부
5. **파일 구조**: `apps/2048/` 안의 파일과 각 파일의 역할
6. **화면 설계**: 레이아웃(글로 설명), 타일 색상 계획(라이트/다크), 모바일 화면 크기별 동작
7. **핵심 로직 설계**: 보드 자료구조, 한 줄을 밀고 합치는 알고리즘, 게임 오버 판정, 입력 처리(키보드/터치)
8. **블로그 삽입 계획**: `index.html`에 넣을 카드의 제목, 설명, 미리보기 방식(iframe 또는 이미지) 제안과 이유
9. **검증 체크리스트**: Review 단계에서 브라우저로 확인할 항목
10. **미정 사항**: 사용자에게 물어봐야 할 결정이 있으면 질문 형태로 적는다.

## 형식
- 한국어, 마크다운. 간결하게 쓴다.
- 마지막 보고에는 spec.md 경로와 핵심 결정 3~5개를 요약한다.
