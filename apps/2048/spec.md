# 2048 구현 계획서

> 상태: **승인됨** (2026-11-02, 미정 사항은 권장안으로 확정). Build 진행 가능.
>
> **확정된 결정**
> 1. 되돌리기: 1단계만 포함 (되돌리면 점수도 함께 복원)
> 2. 진행 중인 판 자동 저장: 제외 (새로고침하면 새 판)
> 3. 블로그 카드 미리보기: iframe (`?preview`)
> 4. 새 게임 버튼: 확인창 없이 즉시 시작
> 5. 추가 조작: WASD 키 포함, 화면 방향 버튼(D-pad)은 제외
> 6. 2048 달성 후 "계속하기": 허용

## 1. 개요
방향키(또는 스와이프)로 숫자 타일을 밀어 같은 숫자끼리 합치고, 2048 타일을 만드는 4×4 퍼즐 게임이다.
`apps/2048/` 안에서 자체 완결되는 순수 HTML/CSS/JS 앱이며, 현재 점수·최고 점수 점수판을 가진다.
블로그의 라이트/다크 테마와 어울리는 색을 쓰고, 모바일에서도 터치로 플레이할 수 있다.

## 2. 게임 규칙
- **보드**: 4×4 칸. 시작 시 타일 2개를 무작위 빈 칸에 놓는다.
- **이동**: 상/하/좌/우 중 한 방향으로 모든 타일을 끝까지 민다. 빈 칸이 있으면 그 방향으로 붙는다.
- **합치기**: 이동 방향에서 서로 맞닿은 같은 숫자 두 타일은 하나로 합쳐지고 값이 두 배가 된다.
  - **한 번의 이동에서 한 타일은 한 번만 합쳐진다.** 예: `[2,2,2,2]` 왼쪽 → `[4,4,0,0]`, `[4,2,2,0]` 왼쪽 → `[4,4,0,0]`, `[2,2,4,0]` 왼쪽 → `[4,4,0,0]`.
  - 이동 방향 쪽(앞쪽) 타일부터 먼저 짝을 짓는다. `[2,2,2,0]` 왼쪽 → `[4,2,0,0]`.
- **점수**: 합쳐질 때마다 만들어진 타일의 값을 점수에 더한다 (2+2 → +4).
- **새 타일**: 이동으로 보드가 **바뀐 경우에만** 빈 칸 하나에 새 타일을 만든다. 2는 90%, 4는 10% 확률.
  이동해도 아무것도 변하지 않으면 새 타일도 없고 점수도 변하지 않는다.
- **승리**: 2048 타일이 처음 만들어지면 "2048 달성!" 안내를 띄운다. "계속하기"(이어서 플레이) / "새 게임" 중 선택. 승리 안내는 한 판에 한 번만 띄운다.
- **게임 오버**: 보드가 가득 차 있고, 상하좌우로 인접한 같은 값 쌍이 하나도 없으면 종료. "게임 오버" 오버레이와 "다시 하기" 버튼을 보여 준다.

## 3. 기능 목록
**필수**
- 방향키 조작 (↑↓←→). 방향키가 페이지를 스크롤하지 않도록 `preventDefault` 처리
- 터치 스와이프 조작 (모바일)
- 현재 점수, 최고 점수 표시
- 새 게임 버튼
- 승리/게임 오버 안내
- 타일 이동·생성·합치기 애니메이션 (CSS transition, `prefers-reduced-motion`에서는 생략)

**선택** (Build에서 시간이 되면, 우선순위 순)
1. 되돌리기 (1단계 또는 최대 N단계)
2. 진행 중인 판 자동 저장/복원 (`localStorage`)
3. WASD 키 지원
4. 화면 방향 버튼(D-pad) — 스와이프가 어려운 사용자용
5. 효과음 (기본 꺼짐) — 이번 범위에서는 제외 권장

## 4. 점수판
- **현재 점수**: 합치기로 얻은 점수의 누적값.
- **최고 점수**: `localStorage`의 `2048:best` 키에 숫자로 저장. 현재 점수가 최고 점수를 넘는 순간 즉시 갱신·저장한다. 저장소 접근 실패 시(`try/catch`) 메모리 값만 사용하고 앱은 정상 동작한다.
- **이번 이동 획득 점수**: 표시한다. 현재 점수 칸 옆에 `+4` 형태로 짧게 떠올랐다가 사라진다 (0점이면 표시 안 함). `aria-live`는 쓰지 않고 현재 점수 값만 `aria-live="polite"`로 알린다.
- 새 게임 시 현재 점수는 0으로, 최고 점수는 유지한다.

## 5. 파일 구조
```
apps/2048/
├── index.html    # 마크업(점수판, 보드 컨테이너, 버튼, 오버레이), 테마 초기화 인라인 스크립트
├── style.css     # 색상 변수(라이트/다크), 레이아웃, 타일·애니메이션 스타일
├── game.js       # 순수 게임 로직 (DOM 접근 없음): 보드, 이동/합치기, 게임 오버 판정
├── main.js       # 진입점: DOM 렌더링, 입력(키보드/터치), 점수 저장, 오버레이 제어
├── spec.md       # 이 계획서
└── review.md     # Review 단계에서 작성
```
- `game.js`와 `main.js`는 ES 모듈(`<script type="module">`)로 연결한다. 전역 변수를 만들지 않는다.
- 외부 라이브러리·CDN·웹 폰트는 쓰지 않는다 (필요 없음). 시스템 폰트 스택 사용.
- 블로그의 `css/theme.css`를 참조하지 않는다 (자체 완결 규칙). 대신 같은 변수 이름과 값을 `style.css`에 복제한다.
- 코딩 규칙은 블로그와 동일: 공백 2칸, 세미콜론, 작은따옴표, 클래스 `kebab-case`, 변수 `camelCase`, 한국어 주석.

## 6. 화면 설계

### 레이아웃 (위에서 아래로)
1. **헤더 줄**: 왼쪽에 제목 "2048", 오른쪽에 "← 블로그" 링크(`../../index.html`).
2. **점수판 줄**: "점수" 박스, "최고" 박스 두 개를 가로로 나란히. 그 옆(또는 아래)에 "새 게임" 버튼.
3. **안내 문구**: "방향키 또는 스와이프로 타일을 밀어 같은 숫자를 합치세요."
4. **보드**: 정사각형 4×4 격자. 칸 사이 간격 일정, 모서리 둥글게. 승리/게임 오버 오버레이가 보드 위에 반투명하게 덮인다.
5. (선택) 되돌리기 버튼은 "새 게임" 옆에 둔다.

- 앱 전체는 가운데 정렬, 최대 폭 약 `500px`. 본문 글자 16px 이상, 버튼은 최소 44×44px.
- 보드 크기: `width: min(100%, 500px)`, `aspect-ratio: 1`. 타일 크기와 위치는 CSS 변수 `--cell`, `--gap`과 `calc()`/퍼센트로 계산해 화면 폭에 비례해 줄어들게 한다.
- 터치 대상(보드)에는 `touch-action: none`을 주어 스와이프 중 페이지가 스크롤되지 않게 한다.

## 7. 핵심 로직 설계

### 보드 자료구조
- `board`: 길이 4의 배열 4개 (`board[row][col]`), 빈 칸은 `0`, 타일은 값(2, 4, 8…).
- 상태 객체 `{ board, score, best, won, keepPlaying, over }`. 되돌리기용 `history` 스택(선택).
- 애니메이션을 위해 타일마다 고유 `id`, 이전 위치, `merged`/`isNew` 플래그를 갖는 타일 객체 배열로 확장할 수 있다. 계획: 로직은 숫자 보드로 계산하고, 렌더링용으로 타일 객체(`{id, value, row, col, isNew, mergedFrom}`)를 함께 유지한다. (단순함을 우선하며 Build 중 더 단순하면 숫자 보드만 사용하고 새 타일/합쳐진 타일 강조 애니메이션만 처리해도 된다.)

### 한 줄을 밀고 합치는 알고리즘 (`slideLine(line) → { line, gained, moved }`)
1. 이동 방향이 "앞"이 되도록 한 줄(길이 4 배열)을 만든다 (왼쪽 기준으로 정규화).
2. 0을 제거해 값만 남긴 배열 `tiles`를 만든다.
3. 앞에서부터 순회하며, 현재 값과 **다음 값이 같으면** 두 배로 합쳐 결과에 넣고 `gained += 합친 값`, 인덱스를 2칸 건너뛴다. 다르면 현재 값만 넣고 1칸 이동. (합쳐진 결과는 같은 이동에서 다시 합쳐지지 않는다.)
4. 결과 뒤를 0으로 채워 길이 4로 맞춘다.
5. `moved = (결과 !== 원래 줄)`.

방향 처리: 왼쪽은 각 행을 그대로, 오른쪽은 행을 뒤집어 처리 후 되돌리고, 위/아래는 열을 추출해 같은 방식으로 처리한 뒤 되돌려 넣는다. 한 번의 `move(dir)`에서 4줄을 처리해 `moved`가 하나라도 true이면 이동 성립.

### 이동 흐름 (`move(dir)`)
1. 4줄 처리 → 새 보드, 총 `gained`, `moved` 계산.
2. `moved`가 false면 상태 변경 없이 종료.
3. 되돌리기용으로 이전 상태 저장(선택), 점수 가산, 최고 점수 갱신.
4. 빈 칸 중 무작위 한 곳에 새 타일 생성 (`Math.random() < 0.9 ? 2 : 4`).
5. 승리 판정: 2048 타일 존재 && `!won` → `won = true`, 승리 안내.
6. 게임 오버 판정 후 렌더링.

### 게임 오버 판정 (`isGameOver(board)`)
- 빈 칸(0)이 하나라도 있으면 → false.
- 모든 칸에서 오른쪽 이웃·아래쪽 이웃과 값이 같은 경우가 하나라도 있으면 → false.
- 위 둘에 모두 해당하지 않으면 → true.
- 새 타일 생성 직후에 판정한다.

### 입력 처리
- **키보드**: `keydown`에서 `ArrowUp/Down/Left/Right`(선택: `w a s d`)를 방향으로 매핑. 수정키(Ctrl/Alt/Meta)가 눌린 경우는 무시. 처리한 키는 `preventDefault()`로 스크롤을 막는다. 오버레이(게임 오버)가 떠 있으면 이동을 무시.
- **터치**: 보드 요소에 `touchstart`/`touchend`(또는 Pointer Events, `pointerdown`/`pointerup`)로 시작·끝 좌표를 기록한다. 이동 거리의 절댓값이 임계값(약 30px, 보드 폭의 10% 중 큰 값) 미만이면 무시(탭). 가로/세로 중 변화량이 큰 축을 방향으로 정한다. 보드에 `touch-action: none`을 적용하고, 필요 시 `touchmove`의 `preventDefault`(`passive: false`)로 스크롤을 막는다.
- 애니메이션 중 입력이 쌓이지 않도록 이동 처리는 동기 계산 후 렌더링만 비동기로 한다 (연타해도 로직 상태는 항상 일관).
- 새 게임 버튼은 확인 없이 즉시 시작한다 (점수가 높을 때만 확인창을 띄울지는 미정 사항 참고).

## 8. 블로그 삽입 계획
**제안: 카드 + 정적 미리보기 iframe**

- **위치**: `index.html`의 `<main>` 안에서 글 목록(`#post-list`) 위에 "앱" 섹션(`<section class="app-cards">`)을 추가한다. 글 목록은 `blog.js`가 렌더링하므로 앱 카드는 정적 HTML로 직접 넣어 `blog.js`를 건드리지 않는다. 카드 스타일은 `css/style.css`에 추가한다 (Embed 단계에서만 블로그 파일 수정).
- **제목**: 2048
- **설명**: "방향키나 스와이프로 숫자 타일을 밀어 합치는 퍼즐 게임. 점수와 최고 점수를 기록합니다."
- **링크**: 카드 제목과 "플레이하기" 링크 → `apps/2048/index.html`
- **미리보기 방식**: `<iframe src="apps/2048/index.html?preview" loading="lazy" title="2048 미리보기" tabindex="-1">`. 카드 안에서 고정 높이(예: 240px)로 보드 일부가 보이게 하고 `pointer-events: none`으로 입력을 막아 클릭 시 카드 링크로 이동하게 한다.
  - `?preview`일 때 앱은 헤더/안내/버튼을 숨기고 보드만 렌더링, 키보드 입력은 받지 않으며 저장된 최고 점수를 덮어쓰지 않는다. 미리보기 보드는 고정된 예시 배치를 보여 준다.
- **이유**: 라이트/다크 테마를 따라가므로 이미지를 두 벌 만들 필요가 없고, 실제 화면과 항상 일치한다. 단점(로딩 비용, 입력 충돌)은 `loading="lazy"`, `pointer-events: none`, `?preview` 모드로 완화한다.
- **대안**: 정적 이미지(`images/2048-preview.svg`). 가볍고 단순하지만 테마별 이미지를 따로 만들어야 하고 UI가 바뀌면 갱신해야 한다. iframe에 문제가 있을 때의 후순위 안.
- 카드는 키보드 포커스 가능한 링크를 가지며 터치 대상 44px 이상을 지킨다. 앞으로 앱이 늘어나면 같은 `.app-card` 마크업을 재사용한다.

## 9. 검증 체크리스트 (Review, 브라우저에서 확인)
**규칙/로직**
- [ ] 시작 시 타일이 정확히 2개이고 값은 2 또는 4
- [ ] 네 방향 모두 타일이 끝까지 밀리고 합쳐진다
- [ ] `[2,2,2,2]`→`[4,4,0,0]`, `[4,2,2,0]`→`[4,4,0,0]`, `[2,2,2,0]`→`[4,2,0,0]` (한 이동에 한 번만 합침)
- [ ] 변화 없는 이동은 새 타일이 생기지 않고 점수도 그대로
- [ ] 새 타일은 2:4가 대략 9:1, 빈 칸에만 생성된다
- [ ] 2048 달성 시 안내가 한 번만 뜨고, "계속하기"로 이어서 플레이 가능
- [ ] 보드가 가득 차도 합칠 수 있는 쌍이 있으면 게임 오버가 아니다
- [ ] 합칠 수 없이 가득 차면 게임 오버 오버레이와 "다시 하기"가 나온다

**점수판**
- [ ] 합칠 때마다 현재 점수가 올바르게 증가하고 `+N` 표시가 보인다
- [ ] 최고 점수가 갱신되고 새로고침 후에도 유지된다
- [ ] 새 게임은 현재 점수만 0으로 되돌린다
- [ ] `localStorage`가 막혀 있어도 오류 없이 동작한다

**입력**
- [ ] 방향키로 조작되고 페이지가 스크롤되지 않는다
- [ ] 모바일(또는 에뮬레이션)에서 스와이프 4방향이 동작하고 탭은 무시된다
- [ ] 스와이프 중 페이지가 스크롤되지 않는다

**화면**
- [ ] 라이트/다크 모두 모든 타일 색의 글자 대비비가 4.5:1 이상
- [ ] 블로그에서 저장한 테마가 앱에도 적용되고 깜빡임이 없다
- [ ] 375px 폭에서 가로 스크롤이 없고 보드가 정사각형으로 유지된다
- [ ] 버튼/링크 터치 대상 44×44px 이상, 본문 글자 16px 이상
- [ ] `prefers-reduced-motion`에서 애니메이션이 줄어든다
- [ ] 콘솔 에러 없음

**삽입 (Embed)**
- [ ] 블로그 메인에 카드가 표시되고 두 테마 모두에서 어울린다
- [ ] 카드(미리보기)를 누르면 `apps/2048/index.html`로 이동한다
- [ ] 미리보기 iframe이 최고 점수나 키 입력에 영향을 주지 않는다
- [ ] 기존 글 목록이 그대로 동작한다 (블로그 다른 파일 변경 없음)
